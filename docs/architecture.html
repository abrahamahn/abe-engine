ENGINE SYSTEM 01 / FRAME START

Platform & foundation

Host events and clocks feed simulation. CPU workers prepare the next frame while the GPU can still be drawing the last one.

Platform HAL First slice

Linux/X11 and Windows/Win32 hosts expose input, visibility and size; Vulkan owns the surface. Extend to Android lifecycle, Apple Metal hosts and browser canvas. Keep console SDK bindings in separately authorized platform modules.

Acceptance test A window survives resize, hide/restore and repeated presentation; verify each claimed target on a real device.

Memory & resource lifetimes Partial

Reusable GPU frame slots and a present semaphore per surface image are in place. Add measured frame arenas, generational pools and per-subsystem RAM/VRAM budgets. Use virtual-memory APIs where platforms expose them.

Acceptance test A warmed-up scene can run and reload without monotonically growing retained resources.

Jobs, tasks and fibers Planned

Start with explicit dependencies, cancellation and a bounded worker pool. Add work stealing, fiber waits and priorities for profiled workloads. The web host needs a single-thread fallback.

Acceptance test Long asset tasks cancel cleanly and never hold the input/render thread.

Math and SIMD First slice

Portable vectors, perspective transforms and scalar geometry come first. Add quaternion, bounds and spline operations to shared core. Select x86 or ARM vector instructions at runtime when necessary; keep a portable WASM path.

Acceptance test Scalar and accelerated kernels agree within documented tolerances on representative transforms.

ENGINE SYSTEM 02 / VISIBILITY AND REQUESTS

World & streaming

The player camera selects visible objects and requests future content. I/O completes asynchronously and feeds later frames.

Entities, hierarchy and spatial queries First slice

Indexed meshes and placed instances can be validated, cooked, and expanded for the current renderer. Add stable entity generations, component stores, hierarchical transforms and spatial indices where needed.

Acceptance test An authored mesh can be instantiated twice, transformed independently, serialized and reloaded.

World cells and HLOD Planned

Partition authored content into independently loadable cells. Build distant proxies offline; choose residency from view, velocity, dependencies and memory pressure.

Acceptance test A roaming sample crosses cells without holes or unbounded memory growth.

Streaming I/O Planned

Provide bounded requests, cancellation, dependency ordering, cache and fallback. Use platform I/O behind the same contract; DirectStorage is an optional Windows path, HTTP/cache storage a web path.

Acceptance test A delayed or corrupt background asset leaves the main loop responsive and produces an actionable error.

ENGINE SYSTEM 03 / SUBMIT AND PRESENT

Rendering

Gather visible instances, schedule passes and submit. A 60 Hz display gives 16.67 ms between frames; 120 Hz gives 8.33 ms.

Direct graphics backends Working slice

The gpu layer (pipelines, bind groups, passes, automatic barriers; shaped so Metal, WebGPU and D3D12 can implement it) runs on first-party Vulkan, offscreen and in native swapchains on Windows and X11. Add Metal and browser WebGPU behind the same interface; DX12 and licensed console backends are separate decisions.

Acceptance test A representative scene draws with equivalent visibility and color on every supported backend.

Render graph and GPU-driven geometry Planned

Move from the current explicit passes to a graph with access declarations, barriers and temporary target reuse. Grow from instancing and culling to mesh clusters or virtual geometry only where the data pays for it.

Acceptance test The graph rejects undeclared resource use and removes a pass whose output is not consumed.

Materials, shaders and lighting Working slice

Shaders are written in a WGSL subset and compiled by Ganbate's own compiler (ganbate-shader) to SPIR-V; MSL, HLSL and WGSL emitters come with their backends. The stylized renderer draws cooked materials and textures with soft cel lighting, two shadow cascades, tiled lamp lights and the lights a game hangs (spots casting the props' shadows), water reflections and a time-of-day sky with weather; each game sets its style in a Look file. Skinned models are skinned on the GPU in every pass. Next come pipeline cache keys and a physically based shading model beside the stylized one. Ray tracing, virtual shadows and advanced GI are optional higher tiers.

Acceptance test Reimporting one material updates the editor and player with the same pipeline and stable cache keys.

Post-processing and resolution First slice

HDR rendering with ambient occlusion, outlines, aerial perspective and mist, bloom, tone mapping and grading, a painterly filter, FXAA in the player and jittered accumulation for stills. Next: separate world resolution from crisp UI, temporal anti-aliasing and optional supported reconstruction techniques. Vendor SDK features require explicit dependency and platform decisions.

Acceptance test Performance tiers preserve legible text and controls while adjusting expensive world passes.

ENGINE SYSTEM 04 / SIMULATION AND POSE

Physics & characters

Advance simulation, sample animation, resolve attachments, and expose the pose and cue times to the renderer.

Collision and dynamics Planned

Begin with picking, bounds, ray casts and collision layers. Extend to broad phase, narrow phase, fixed-step rigid bodies and constraints. Vehicles, cloth and destruction are later modules.

Acceptance test A moving character collides reproducibly with a simple scene and the editor displays the contact.

Skeletal animation and motion matching Planned

Import skins and clips, blend poses, seek by timestamp, attach to sockets and fire discrete cues. Motion matching belongs above a validated clip database.

Acceptance test Backward seeks and reconnects never duplicate a cue. A prop releases from the sampled socket pose.

IK, facial animation and cinematics Planned

Use constrained IK, morph targets, facial layers, camera cuts and timeline tracks. Extend to physical characters and phoneme-driven animation when real content requires them.

Acceptance test The same saved timeline scrubs to the same pose in the editor and a packaged player.

ENGINE SYSTEM 05 / PLAYER AND WORLD RESPONSE

Gameplay services

Translate input into game-owned intent, update local presentation, and dispatch audio, navigation and UI work.

Game modules, scripting and UI Planned

Define a Rust game-module lifecycle, events, focus/navigation, text shaping and scalable HUD layout. Keep editor scripting or a visual graph optional and isolated from game authority.

Acceptance test Two unrelated games use the same engine APIs and register different components and actions.

Navigation, AI and crowds Planned

Provide spatial queries, navigation meshes, behavior scheduling and update budgets. Content determines behavior trees, utility decisions and crowd fidelity.

Acceptance test A non-card sample can navigate around an obstacle while distant agents update less often.

Audio Planned

Build buses, mix, schedule time-aligned cues, spatialize emitters and stream music; later add occlusion and environmental reverb.

Acceptance test Seek a timeline without playing a one-shot twice, and recover from audio interruption.

Networking and replay Planned

Expose clocks, snapshots, resource identifiers and replay hooks. Each game chooses its server authority, security policy, rollback and prediction needs.

Acceptance test A game can reconstruct a viewer-authorized state after reconnect; a purely local game runs with no network.

ENGINE SYSTEM 06 / OUTSIDE THE FRAME BUDGET

Studio tools & assets

Editors and cookers produce versioned content. The runtime consumes their outputs; offline builds do not belong in the 16.67 ms frame.

Importer, cooker and packages First slice

The cooker reads a bounded static GLB subset (meshes, PBR material factors, PNG base-colour/normal/emissive textures, point lights) with first-party zlib/PNG codecs and writes a deterministic GBEW v2 world with mip chains. Next come dependency manifests, content hashes, GPU-compressed texture formats, audio formats and incremental target packages.

Acceptance test A clean rebuild produces identical bytes; corrupt inputs and unsupported features fail explicitly.

World editor and collaboration Planned

Build hierarchy, viewport selection, gizmos, inspector, undo transactions, play-in-editor, stable references and reviewable per-object or per-cell files. World, material, particle and quest editors share the runtime.

Acceptance test Two contributors edit different objects, merge them, and reopen a valid scene without overwriting each other.

Timeline and material authoring Planned

Edit camera and animation tracks, cue times, shader graphs and VFX with the same renderer used by the player. Build visual authoring on versioned data formats.

Acceptance test Change one cue once, then see it in the editor, a headless replay and a standalone build.

Profiling, regression and unattended tests First slice

Headless and presented Vulkan tests exist. Expand frame traces, resource counters, crash diagnostics, image comparisons, replay bots and long-session runs.

Acceptance test A regression shows the failing fixture, target, driver and reproducible trace; a software-driver run is labeled as such.

“Working slice” and “First slice” describe limited implementations. “Planned” identifies design targets. Optional platform and vendor integrations require their own SDK, authorization and device qualification. All product code and content stay in the client project.
